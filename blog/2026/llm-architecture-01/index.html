01Transformer 如何并行，以及它的数学形式

1.1 RNN 与 Transformer 的并行差异（4 词例子）

假设输入是一句只有 4 个词的句子：["我", "喜欢", "深度", "学习"]（对应 4 个词向量 $x_1, x_2, x_3, x_4$）。

RNN 像接力赛，必须一个等一个：RNN 的核心递推公式是 $h_t = f(h_{t-1}, x_t)$，当前词的状态强依赖上一个词的输出。即使 GPU 有上万个核心，算第 2 个词时也只能等第 1 个词算完。如果句子长到 4096 个词，RNN 这一层就必须串行跑 4096 步。

Transformer 像大合唱，把词拼成矩阵一次算完：Transformer 砍掉了序列方向的链式依赖，直接把 4 个词叠成一个 $4 \times d$ 的大矩阵 $X$，在序列维度上把串行步数压成了 $O(1)$：

  1. 同时算所有词的 $Q, K, V$：$Q = XW_Q,\; K = XW_K,\; V = XW_V$。三次大矩阵乘法，4 个词互不依赖，GPU 在同一拍全部算出。
  2. 一次矩阵乘法算完所有两两关系：$S = \frac{QK^\top}{\sqrt{d_k}}$，直接算出一个 $4 \times 4$ 的注意力打分表（16 个格子同时算出）。在自回归语言模型训练时，只要加上 Causal Mask（因果掩码），把右上角盖成 $-\infty$（Softmax 后权重为 $0$），就能在不偷看未来词的前提下，让 4 个位置的预测任务在同一拍并行完成。
  3. 加权求和与 FFN 同样全并行：$\text{Out} = \text{Softmax}(S + \text{Mask})V$ 以及后续逐词独立运算的 FFN，在序列维度上完全互不等待。
KEY INTUITION · 区分训练并行与生成串行

训练与推理 Prefill（读入提示词）时所有输入词都在手里，完全并行；但在推理 Decode（逐字生成回答）时，必须先吐出第 5 个词才能计算第 6 个词，因此生成阶段本身仍是逐 token 串行的（工程上借助 KV Cache 避免重复计算前面已读过的历史）。

1.2 标准 Transformer 的数学形式

设输入词嵌入加位置编码为初始状态 $H^{(0)} \in \mathbb{R}^{m \times d}$（$m$ 为序列长度，$d$ 为隐藏维度），模型共有 $L$ 层，第 $l = 1, 2, \dots, L$ 层拥有自己独立的一套参数 $\theta^{(l)}$：

  • 原始论文版（Post-LN，2017）： $$A^{(l)} = \text{LayerNorm}\Big(H^{(l-1)} + \text{MHA}^{(l)}\big(H^{(l-1)}\big)\Big)$$ $$H^{(l)} = \text{LayerNorm}\Big(A^{(l)} + \text{FFN}^{(l)}\big(A^{(l)}\big)\Big)$$
  • 现代 LLM 标配版（Pre-LN，如 GPT / LLaMA / Qwen）：把归一化移到子层输入端，让深层梯度回传更稳定： $$A^{(l)} = H^{(l-1)} + \text{MHA}^{(l)}\big(\text{Norm}(H^{(l-1)})\big)$$ $$H^{(l)} = A^{(l)} + \text{FFN}^{(l)}\big(\text{Norm}(A^{(l)})\big)$$

若把单层打包记为算子 $F_{\theta^{(l)}}$，标准 Transformer 就是固定 $L$ 步的复合递推，最后经归一化与词表头投影输出概率分布：

$$H^{(l)} = F_{\theta^{(l)}}\big(H^{(l-1)}\big), \quad l = 1, \dots, L \qquad \Longrightarrow \qquad Y = \text{Softmax}\big(\text{Norm}(H^{(L)}) W_{\text{vocab}}\big)$$

从动力学视角来看，Pre-LN 不断往同一条“残差流（Residual Stream）”做增量更新 $H^{(l)} = H^{(l-1)} + \Delta H^{(l)}$，很像用一个时变算子对隐状态做 $L$ 步离散演化（类似神经 ODE 的 Euler 离散化）。写成极简伪代码，一个 $L$ 层的标准 Transformer 前向过程如下：

# 标准 Transformer：L 个独立层，参数不共享
h = embed(tokens) + pos_emb
for layer in self.layers:
    h = h + layer.attn(norm(h))
    h = h + layer.ffn(norm(h))
logits = lm_head(norm(h))

02Encoder 与 Decoder：分工、并行性与流派演进

最初的 Transformer（2017）是为机器翻译设计的，模型分为 Encoder（编码器） 和 Decoder（解码器） 两半。

2.1 分工与三流派对照

以将 "I love deep learning" 翻译为 "我喜欢深度学习" 为例：Encoder 像“阅读理解员”，双向全看一次性读通整句英文并产出语义笔记；Decoder 像“逐字写手”，只能看已写出的中文字，同时通过 Cross-Attention 随时翻阅 Encoder 的笔记，一个词一个词往外生成。

架构流派 单层内部子模块 注意力视角 代表模型与现状
Encoder-Decoder Enc: Self-Attn + FFN
Dec: Masked Self-Attn + Cross-Attn + FFN		 编码端双向全看；解码端单向因果 + 跨注意力 原始 Transformer、T5、BART
Encoder-only Self-Attn + FFN 双向全看 BERT、RoBERTa、BGE Embedding（擅长理解、分类、向量检索）
Decoder-only Masked Self-Attn + FFN 单向因果 GPT、LLaMA、Qwen、DeepSeek 及现代 Loop 模型（现代通用 LLM 主流）

2.2 有 Encoder 也能并行吗？为什么现代通用 LLM 砍掉了它？

Encoder 完全可以并行，而且比 Decoder 更纯粹——Encoder 读输入序列时不需要 Causal Mask，所有词双向互看，在训练和推理读入阶段都可以一次性拼成大矩阵全并行算完。真正不能并行的只是自回归“逐字吐出回答”的解码阶段。

现代通用大语言模型砍掉 Encoder 并非因为它不能并行，而是出于 4 个很现实的工程与效果考量：

  1. 参数利用率被劈成两半：同样 10B 参数，一半放 Encoder、一半放 Decoder，面对“输入 10 万字只答 10 个字”或“输入 10 个字写 5000 字代码”的极端任务比例时，总有一半参数负荷不均；Decoder-only 让 100% 的参数既能读又能写。
  2. 多轮对话的 KV Cache 复用别扭：Decoder-only 把历史对话与新问题拼成一条序列，前缀缓存（Prefix Caching）天然复用；Encoder-Decoder 下一轮必须把上一轮 Decoder 吐出的回答重新塞回 Encoder 双向重算。
  3. 预训练效率与涌现规律：Decoder-only 用“预测下一个词”，每个 token 都贡献梯度（100% 样本利用率），在超大规模无标注语料上扩展上下文学习（In-Context Learning）能力更顺畅。
  4. 系统与算子极简：全网只有一种对称的 Block，万卡分布式切分与推理引擎（如 vLLM、FlashAttention）优化最干净。
NOTE · Encoder 并没有消失

Encoder 退出了纯文本通用 LLM 主干后，在两个专职岗位上依然是绝对主力：向量检索 / Embedding 模型（只需要把文本压成高质量向量，不需要生成）以及多模态大模型的视觉 / 音频前端编码器（Vision / Audio Encoder）。

03MHA、FFN 与模型维度配比

3.1 MHA 与 FFN 的分工

在每一层 Transformer 中，MHA 和 FFN 构成了互补的黄金分工：

  • MHA（Multi-Head Attention，横向搬运 / Token Mixing）：每个词生成 Query（想找什么）、Key（有什么标签）和 Value（具体内容），通过多头机制让不同注意力头分别盯住指代消解、主谓宾语法或长距离呼应，把上下文其他位置的信息按动态权重搬运过来。但它本质上只是对 Value 做加权平均，如果只堆 MHA 不加 FFN，模型缺乏非线性变换能力，特征会越平均越模糊（Rank Collapse）。
  • FFN（Feed-Forward Network，纵向深加工 / Channel Mixing）：对每个词自己独立做一次“升维 → 非线性激活 → 降维”，完全不看其他词。它不仅提供核心非线性语义融合（例如把搬到一起的 "苹果" 与 "发布会" 消歧为科技公司），更被可解释性研究证实充当了大模型的内置 Key-Value 参数化知识库——因此典型稠密 LLM 中 FFN 占约 $2/3$ 的参数量，MoE（混合专家）架构也几乎只把 FFN 拆成多专家。
KEY INTUITION · 搬运线索 + 查库推理

预测 "埃菲尔铁塔位于 [__]" 时，MHA 先把前文的 "埃菲尔铁塔" 与 "位于" 搬运到末尾位置；随后的 FFN 在独立通道里命中内部记忆条目，把指向 "巴黎" 的特征写回残差流。多层堆叠就是不断重复“横向收集线索 → 纵向查库推理”。

3.2 隐藏维度 $d_{\text{model}}$ 与 FFN 宽度 $d_{\text{ff}}$

$d_{\text{model}}$ 是贯穿全网残差流主干道的“标准包裹尺寸”；$d_{\text{ff}}$（代码配置里常叫 intermediate_size）则是仅存在于 FFN 内部的“临时大工作台尺寸”。

拉大 $d_{\text{model}}$ 会让 MHA、FFN 和 KV Cache 显存全部一起涨；而只拉大 $d_{\text{ff}}$ 完全不增加推理时的 KV Cache 显存，这也是 MoE 只扩展 FFN 而不动主干维度的根本原因。

  1. 单头维度 $d_{\text{head}}$ 几乎固定在 $64$ 或 $128$（如 $32\text{ 头} \times 128 = 4096$）。

  3. 单层标准稠密 Transformer 参数量约为 $12 d_{\text{model}}^2$（MHA 约 $4d^2$ + FFN 约 $8d^2$）。

04现代 LLM 的四个核心组件（附手算例子）

现代 Decoder-only 模型普遍用 RMSNorm + SwiGLU + GQA + RoPE 替换了 2017 年版的对应零件。

4.1 RMSNorm（均方根归一化）

LayerNorm 要先减均值（平移居中）再除标准差（缩放）；RMSNorm 直接删掉减均值和偏置项 $\beta$，只做均方根缩放：

$$\text{RMS}(x) = \sqrt{\frac{1}{d}\sum_{i=1}^d x_i^2 + \epsilon}, \qquad \text{RMSNorm}(x) = \frac{x}{\text{RMS}(x)} \odot g$$
WORKED EXAMPLE · RMSNorm 手算对照

设输入 $x = [3, 4]$，缩放参数 $g = [1, 1]$，忽略 $\epsilon$：

  • LayerNorm：先算均值 $\mu = (3+4)/2 = 3.5$，减均值成 $[-0.5, +0.5]$，再除以标准差 $0.5$ 得 $[-1, +1]$。
  • RMSNorm：不算均值，直接算均方根 $\text{RMS} = \sqrt{(3^2 + 4^2)/2} = \sqrt{12.5} \approx 3.536$，相除得 $[0.849,\; 1.131]$。

为什么去掉“减均值”训练一样稳，且速度更快？

  • 训练一样稳：深层网络防崩溃主要靠缩放不变性（Re-scaling）把向量幅度锁死在固定尺度上，避免梯度爆炸或消失；“平移居中”实测贡献极微，微小的均值偏移很容易被后续线性层和残差流吸收。
  • 速度更快：Norm 属于显存带宽受限（Memory-bound）算子。RMSNorm 只需做 1 次全局平方和归约（LayerNorm 要算均值和方差 2 个统计量），砍掉了 $\beta$ 参数的读写以及反向传播里均值通路的梯度计算。一个 80 层模型每次前向要做 160 次 Norm、反向再做 160 次，算子层面通常快 10%–40%。

4.2 SwiGLU（门控激活 FFN）

传统 FFN 只有一条路：ReLU(x W_up) W_down。SwiGLU 把升维拆成候选特征路与门控开关路：

$$\text{SwiGLU}(x) = \Big(\text{SiLU}(x W_{\text{gate}}) \odot (x W_{\text{up}})\Big) W_{\text{down}}, \qquad \text{SiLU}(z) = \frac{z}{1 + e^{-z}}$$

为什么 $d_{\text{ff}}$ 不变会多 50% 参数？工程上怎么打平？
设每个矩阵参数量为 $A = d_{\text{model}} \times d_{\text{ff}}$：老式 FFN 有 2 个矩阵（W_up, W_down），总参数 $= 2A$；SwiGLU 多了 W_gate，共 3 个矩阵，若 $d_{\text{ff}}$ 不变则总参数 $= 3A$，正好比 $2A$ 多出 $(3A-2A)/2A = \mathbf{+50\%}$。因此工程上会把 $d_{\text{ff}}$ 缩成原来的 $\frac{2}{3}$（从 $4d$ 降到 $\frac{8}{3}d \approx 2.67d$），使总参数 $3 \times \frac{2}{3}A = 2A$ 严丝合缝打平（例如 $d_{\text{model}}=3072$ 时，ReLU 宽 $12288$ 与 SwiGLU 宽 $8192$ 总参数同为 75.5M）。

缩窄 $\frac{1}{3}$ 宽度，不会降低表达能力吗？
不会，反而更强。因为总参数预算一分没少，且单个 SwiGLU 神经元拥有两路相乘的软逻辑 AND 门能力（例如同时检测“是苹果” $\times$ “科技语境”）；老式 ReLU 只有单路分段线性叠加，需要多个神经元凑阈值才能拟合二次交叉特征，还常存在 Dead ReLU（负半轴归零闲置）问题。

WORKED EXAMPLE · SwiGLU 三矩阵完整手算（d=2 → 3 → 2）

设输入向量 $x = [1, 2]$：

  1. 候选特征路：$u = [1, 2] \begin{pmatrix} 1 & 0 & 2 \\ 0 & 1 & 1 \end{pmatrix} = [1,\; 2,\; 4]$。
  2. 门控开关路：先算 $x W_{\text{gate}} = [1, 2] \begin{pmatrix} 2 & -2 & 0 \\ 0 & 0 & 1 \end{pmatrix} = [2, -2, 2]$，再过 $\text{SiLU}$ 得 $g \approx [1.76,\; -0.24,\; 1.76]$。
  3. 逐元素相乘过滤：$h = g \odot u = [1.76,\; -0.48,\; 7.04]$（第 2 个特征被压扁，第 3 个被放大）。
  4. 降维回主干：$y = [1.76,\; -0.48,\; 7.04] \begin{pmatrix} 1 & 0 \\ 0 & 1 \\ 0.5 & 0.5 \end{pmatrix} = [5.28,\; 3.04]$。
u = x @ W_up                   # (1, 2) -> (1, 3)
g = F.silu(x @ W_gate)         # (1, 2) -> (1, 3)
y = (g * u) @ W_down           # (1, 3) -> (1, 2)

4.3 GQA（分组查询注意力）

推理生成时必须把历史 token 的 $K, V$ 缓存在显存里（KV Cache）。GQA 让多个 Query 头分组共享同一套 Key / Value 头，在几乎不损失理解力的前提下大幅砍掉显存搬运量。

4.4 RoPE（旋转位置编码）完整拆解

1. 为什么偏好“只看相对位置”？
因为语言具有平移不变性："黑猫跳上了桌子" 不管出现在文章第 10 字还是第 10,000 字，词与词的相对修饰关系不变。把绝对位置编号直接加到词向量上容易让位置与语义混淆，超过训练长度就会分布外崩溃。

2. RoPE 插在哪里？怎么起作用？
RoPE 不加在最开始的词嵌入里，也不修改 Value（$V$），只插在算完 $Q, K$ 之后、算注意力点积之前：

WORKED EXAMPLE · RoPE 4 维向量旋转手算

设位置 $n=1$ 的词和位置 $m=3$ 的词，原始向量恰为 $k_1 = [1, 0, 1, 0]$、$q_3 = [1, 0, 1, 0]$。4 维分成两组，转速分别为 $\theta_0 = 30^\circ/\text{词}$、$\theta_1 = 5^\circ/\text{词}$：

  • 旋转 $k_1$（乘 $n=1$）：前 2 维转 $30^\circ \to [0.866, 0.5]$，后 2 维转 $5^\circ \to [0.996, 0.087]$。
  • 旋转 $q_3$（乘 $m=3$）：前 2 维转 $90^\circ \to [0, 1]$，后 2 维转 $15^\circ \to [0.966, 0.259]$。
  • 点积 $q_3^{\text{rot}} \cdot k_1^{\text{rot}}$：前 2 维贡献 $0.5 = \cos(60^\circ)$，后 2 维贡献 $0.985 \approx \cos(10^\circ)$，总分 $= \mathbf{1.485}$。

如果把这两个词同时平移到第 101 位和第 103 位，它们的角度差依然是 $(103-101)\times 30^\circ = 60^\circ$ 和 $10^\circ$，点积结果一分不差还是 1.485！代码实现也只需逐组做两次乘加：

x1_rot = x1 * cos(m * theta) - x2 * sin(m * theta)
x2_rot = x1 * sin(m * theta) + x2 * cos(m * theta)

3. 为什么要有多个角度参数？怎么分配？固定还是可变？

  • 为什么不能只有一个转速：全用快转速（每 10 词一圈），第 1 词和第 11 词会撞车；全用慢转速（10 万词一圈），相邻两词角度差小到挤在一起，局部语法会糊掉。所以必须像时钟一样同时配秒针、分针和时针。
  • 怎么分配转速：以 $d=128$ 为例，分成 $i = 0, 1, \dots, 63$ 共 64 组，按等比数列指数递减分配： $$\theta_i = \text{base}^{-\frac{2i}{d}} \qquad (\text{经典 } \text{base} = 10000)$$ 第 0 组 $\theta_0 = 1.0$ 弧度/词（最快秒针），第 32 组 $\theta_{32} = 0.01$，第 63 组 $\theta_{63} \approx 0.000115$（约 5.4 万词转一圈，最慢时针）。
  • 固定还是可变：在正常训练和未超长推理时，转速表 $\theta_i$ 是写死固定的，随位置 $m$ 线性增大的是实际旋转角 $m \cdot \theta_i$；只有在强行外推超长上下文时，工程上才不得已去改 $\theta_i$ 或 base。

4. 长上下文补丁：PI、NTK 与 YaRN（3 指针数值例）
当 4K 训出的模型遇到 16K（拉长 4 倍）文本时，高频秒针已转过几百圈而失去圈数区分，而低频时针在训练时只走过很小角度（如 $14.4^\circ$），到 16K 时却转到 $57.6^\circ$——闯入训练从未见过的角度盲区导致崩溃。

指针（$d=6$，原始 base=10000） 原始转速 (4K) PI（全部除以 4） NTK（base 改 $8\times \to 80000$） YaRN（分段精细处理）
秒针（$i=0,\; \text{base}^0$） $1.0$ $0.25$（相邻词挤糊） $1.0$（0 次方不变，保住） $1.0$（高频区完全不动）
分针（$i=1,\; \text{base}^{-1/3}$） $0.0464$ $0.0116$ $0.0232$（慢 2 倍） $1 \to 1/4$ 线性平滑过渡
时针（$i=2,\; \text{base}^{-2/3}$） $0.00215$ $0.00054$（不越界） $0.00054$（正好慢 4 倍） $0.00054$（低频区按 PI 拉回）

YaRN 在此基础上还额外增加了注意力温度缩放（把超长上下文中被摊平的 Softmax 分布重新拉尖），虽然效果最稳，但超参数多、每次扩窗通常仍需少量微调。

05RoPE 的四个副作用与 NoPE 的兴起

上下文迈向几十万乃至百万 token，或结合新型低秩注意力架构时，RoPE 暴露出了四个明显的副作用：

5.1 远程衰减（Long-Term Decay）

设 3 组维度语义完全匹配，点积正比于 $\cos(\Delta\theta_1) + \cos(\Delta\theta_2) + \cos(\Delta\theta_3)$：当距离很近（$\Delta \approx 0$）时三组余弦全在 $0^\circ$ 附近，同向叠加得 $1 + 1 + 1 = \mathbf{+3}$；当距离很远（如 $\Delta = 500$）时各组指针早就散开，假设分别落到 $60^\circ, 180^\circ, 300^\circ$，求和变成 $+0.5 - 1.0 + 0.5 = \mathbf{0}$，正负互相抵消。RoPE 因此天然偏爱近距离词、压低远距离分数。

5.2 Attention Sink 霸占低频维度与“中间迷失”

很多人容易误以为 RoPE 是贴在向量旁边的独立位置标记，其实RoPE 直接旋转的是 $Q$ 和 $K$ 语义向量本身——128 维里既没有专门的“位置位”，也没有专门的“垃圾桶位”。

同时，Softmax 规定所有词的权重之和必须等于 100%。当模型遇到不需要从前文搬运信息的虚词（如 "的"）时，它自发学会了把多余注意力（经常 60%–90%）全倒给句首第 1 个词 <BOS>（Attention Sink）。

TRADE-OFF · 4 维磁铁例：为什么垃圾桶一定要抢低频通道？

设前 2 维 (d0, d1) 每词转 $90^\circ$（高频），后 2 维 (d2, d3) 走 1000 词才转 $1^\circ$（低频）。读到第 1001 个词 "的" 时，若把锚点常数写进高频前 2 维，走几步就从 $+100$ 翻成 $-100$，彻底脱靶；只有塞进几乎不转的低频后 2 维，才能跨万字稳稳对齐：

$$k_{\text{BOS}} = [0, 0,\; \mathbf{10, 0}], \qquad q_{\text{的}} = [0, 0,\; \mathbf{10, 0}] \implies q_{\text{的}}^\top k_{\text{BOS}} = \mathbf{+100}$$

后果：第 1002 个词 "他" 想用稀缺的低频维度跨越 1000 词去捞第 5 个词 "张三"（$k_{\text{张三}} = [1, 0,\; 2, 0]$）时，只要在 d2 上带一点正数，就会被 <BOS> 这块 [10, 0] 大磁铁抢走权重，严重挤占长距离语义检索空间。

5.1 与 5.2 共同造就了超长文档中的 Lost in the Middle（中间迷失）：开头因 Sink 权重高，末尾因无远程衰减权重高，夹在中间的几万字最容易被忽略。（后续有些架构会在 Softmax 分母中额外引入独立可学习标量 sink_bias，把垃圾桶从低频语义维度中解放出来。）

5.3 与 MLA（低秩 KV 压缩）打架

DeepSeek 的 MLA 把历史 Key 压成一个小向量 $c_n$（需要时再乘解压矩阵 $W_{UK}$ 还原）。若没有 RoPE，推理时可利用结合律直接把 $W_{UK}$ 吸收进 Query 矩阵中，根本不用解压历史缓存：

$$q_m^\top k_n = (W_Q x_m)^\top (W_{UK} c_n) = x_m^\top (W_Q^\top W_{UK}) c_n$$

但插进 RoPE 后，中间硬生生卡了一个随距离 $(n-m)$ 变化的旋转矩阵 $R_{n-m}$：

$$q_m^\top k_n = x_m^\top W_Q^\top R_{n-m} W_{UK} c_n$$

$W_Q^\top$ 与 $W_{UK}$ 碰不到一起，线性吸收失效。MLA 被迫做出妥协（Decoupled RoPE），把 Key 劈成“可压缩的语义部分 + 一份单独存且不压缩的 RoPE 旁路”。

5.4 缺乏全局坐标感

就像一条打了 1000 个结、每个结只知道自己与邻居相对距离的绳子，纯相对位置本身无法直接回答“我现在是第 3 个结还是第 800 个结”，只能依赖 Causal Mask 左边界（<BOS>）间接推算。

5.5 NoPE 必须配合 decay（衰减）才能用吗？

既然 RoPE 有这么多麻烦，能不能干脆用 NoPE（No Positional Embeddings，零位置编码）？NoPE 并非必须配合 decay 才能用，它只需要某种能够打破位置对称性的搭档机制。Decoder 架构里有三种常见用法：

  1. 纯 Decoder-only + NoPE（不用 decay，也不用 RoPE）：依靠 Causal Mask 本身的三角不对称性（第 1 词只能看 1 个词，第 2 词能看 2 个词……），模型过完第 1 层后自己就能硬算出位置，但收敛慢、局部语序弱。
  2. 局部 RoPE + 全局 NoPE（如 Llama 4 的 iRoPE）：不用 decay，而是每几层带 RoPE 的局部滑窗注意力搭配 1 层 NoPE 全局注意力。
  3. 带 decay 的线性注意力 + 全局 NoPE（如 Kimi K3）：每 3 层 KDA（Kimi Delta Attention）搭配 1 层 NoPE 的 Gated MLA 全局注意力。

唯一绝对不能用 NoPE 的场景是双向 Encoder（无 Causal Mask 也无 decay）——所有词完全对称互看，去掉位置编码后 "猫咬狗" 和 "狗咬猫" 输出完全相同，彻底退化成无序词袋。

06KDA（Kimi Delta Attention）的运行机制与代价

在 Kimi K3 的 3 层 KDA + 1 层 NoPE Gated MLA 架构中，KDA 把历史压缩进固定大小的状态矩阵，并同时接管了“记录词序与相对距离”的工作。

6.1 衰减因子如何隐式记住词序？（褪色黑板与双通道例子）

把衰减更新简化成 $S_t = \alpha \cdot S_{t-1} + x_t$（每来一个新词，先把旧记忆乘以 $\alpha$ 变淡）。设 $\alpha = 0.8$，依次读入 ["我", "喜欢", "深度", "学习"]，最终状态变为：

$$S_4 = \mathbf{0.512}\,\text{"我"} + \mathbf{0.64}\,\text{"喜欢"} + \mathbf{0.8}\,\text{"深度"} + \mathbf{1.0}\,\text{"学习"}$$

不用任何 RoPE 编号，"猫 咬 狗" 与 "狗 咬 猫" 算出的状态完全不同——褪色的程度本身就是天然的距离尺子。

逐通道衰减 + NoPE 全局层如何配合？
假设一篇 500 句的长文，开头写 "张三住在北京"，第 502 句写 "猫追着狗跑，它很害怕"，第 503 句问 "张三住在哪里？"。经过前 3 层 KDA 时，快衰减通道（如 $\alpha_1=0.5$）只管最近 2–3 个词的精细语序并快速忘掉前文干扰；慢衰减通道（如 $\alpha_2=0.999$）在 500 句后仍保留 $0.999^{500} \approx 0.61$ 的长线背景。等流到第 4 层（NoPE 全局 MLA）时，"北京" 早已带上上下文角色印记，NoPE 层只需跨 500 句做纯语义检索即可精准命中，且 MLA 低秩矩阵吸收畅通无阻。

6.2 KDA 完整公式与 $2\times 2$ 手算例子

KDA 在 Gated DeltaNet（GDN）的标量衰减基础上改成了逐通道向量衰减，核心公式为：

$$S_t = S_{t-1}\,\mathrm{Diag}(\alpha_t)\big(I - \beta_t k_t k_t^\top\big) + \beta_t v_t k_t^\top, \qquad o_t = S_t q_t, \qquad \alpha_t \in (0, 1)^{d_k}$$

它可以被看作一本固定大小的“可擦写记忆本”：$S_{t-1}\,\mathrm{Diag}(\alpha_t)$ 负责按通道整体淡化旧记忆，$(I - \beta_t k_t k_t^\top)$ 是只擦除 $k_t$ 方向的定点橡皮擦，最后加上 $\beta_t v_t k_t^\top$ 写入新值。

WORKED EXAMPLE · KDA 2×2 矩阵逐行验算

新输入“张三搬去了上海”：$v_t = [2, 6]^\top$，指向地点 $k_t = [1, 0]^\top$，$\beta_t = 1$，$\alpha_t = [0.5, 0.9]^\top$：

  1. 逐通道衰减：$S' = \begin{pmatrix} 10 & 0 \\ 0 & 8 \end{pmatrix}\begin{pmatrix} 0.5 & 0 \\ 0 & 0.9 \end{pmatrix} = \begin{pmatrix} 5 & 0 \\ 0 & 7.2 \end{pmatrix}$。
  2. 定点擦除旧地点：$S_{\text{erased}} = \begin{pmatrix} 5 & 0 \\ 0 & 7.2 \end{pmatrix}\begin{pmatrix} 0 & 0 \\ 0 & 1 \end{pmatrix} = \begin{pmatrix} \mathbf{0} & 0 \\ \mathbf{0} & 7.2 \end{pmatrix}$。
  3. 写入新地点：$S_1 = \begin{pmatrix} 0 & 0 \\ 0 & 7.2 \end{pmatrix} + \begin{pmatrix} 2 & 0 \\ 6 & 0 \end{pmatrix} = \begin{pmatrix} \mathbf{2} & 0 \\ \mathbf{6} & 7.2 \end{pmatrix}$。
  4. 读出验证：查地点 $q=[1,0]^\top \implies S_1 q = [2, 6]^\top$（干净读出“上海”，无“北京”残留）；查职业 $q=[0,1]^\top \implies [0, 7.2]^\top$（“医生”仍在）。

6.3 方向 $k_t$ 怎么决定？可以更新吗？

$k_t$ 既不是人工写死的，也不是固定坐标轴，而是通过可学习线性层加 $L_2$ 归一化动态算出来的（$L_2$ 归一化能防止转移矩阵特征值过大导致状态爆炸）：

$$k_t = \frac{W_K x_t}{\|W_K x_t\|_2}$$
  • 推理时动态变化且可覆盖：第 $t$ 词讲“地点”，$W_K$ 把它映射到“地点方向”；第 $t+1$ 词讲“职业”，$k_{t+1}$ 切到“职业方向”；500 步后再提“搬家”，$W_K$ 再次指向“地点方向”并覆盖旧记忆。
  • 训练时持续学习寻址规则：$W_K$（以及算 $\alpha_t, \beta_t, q_t, v_t$ 的投影层）都会通过反向传播更新，逐步学会把不同类别的信息尽量映射到彼此接近正交的方向上以减少串台。（在更近期的 GDN2、EDA 等探索中，研究者甚至尝试把“擦除方向”和“写入方向”拆成两个向量，但也带来了谱范数可能大于 1 的新稳定性难题。）

6.4 KDA 的四个现实代价

TRADE-OFF · O(1) 解码成本背后的四笔账
  1. 固定状态的容量天花板：$S_t$ 尺寸是固定的（例如 $128 \times 128$），最多互不干扰地容纳有限个正交键值对。一旦遇到超长序列中的密集精确检索（如大海捞针 / 长电话簿），不同 Key 会互相覆盖——这正是 Kimi K3 必须以 3:1 保留全局 MLA 层的原因。
  2. 并行训练与算子工程难度大：KDA 的转移矩阵 $\mathrm{Diag}(\alpha_t)(I - \beta_t k_t k_t^\top)$ 属于对角加秩一（DPLR）结构，在 GPU 上做并行训练必须分块（Chunkwise）并执行块内下三角矩阵求逆，编写高效 CUDA / Triton Kernel 的门槛显著高于标准注意力。
  3. 低精度数值更脆弱：块内求逆、$k_t$ 归一化以及衰减门控在 bf16/fp16 下比 Softmax 注意力更容易出现数值漂移或梯度爆炸，工程中常需把关键衰减项或归一化保留在 fp32 精度。
  4. 推理前缀缓存（Prefix Caching）粒度变粗：标准 KV Cache 按 token 线性追加，切片复用非常灵活；KDA 将历史揉进滚动矩阵 $S_t$，若要复用前缀缓存，只能按固定块边界保存状态矩阵快照。
